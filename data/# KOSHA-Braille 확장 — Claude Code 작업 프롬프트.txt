# KOSHA-Braille 확장 — Claude Code 작업 프롬프트 (상세판)

## 배경
"KOSHA-Braille: Infrastructure-Grade Accessibility for Korean Chemical Safety
Information" (Universal Access in the Information Society, Brief Report)이
2026-08-19 최종 Accept 확정됨. 이 논문의 핵심 파이프라인은 화학물질명(대부분
라틴/그리스 어원 조합)을 규칙 기반으로 한국어 점자 표기로 변환하는 인프라다.

전문가(점역사, 수어 전문가, CV 전문가 등)에게 실제로 검증/자문을 맡길지는
아직 결정된 바 없다. 이 프롬프트는 그 결정과 무관하게, **사람 개입 없이 먼저
진행 가능한 범위**를 정리한 것이다. 트랙별로 독립적으로 진행 가능하며, 우선순위
순서대로 착수한다.

---

## 트랙 A — 화학물질명 파이프라인의 인접 도메인 확장 (최우선)

### 목표
기존 KOSHA-Braille 파이프라인(화학물질명 → 라틴/그리스 어원 분해 → 한국어
점자 표기 변환)을 일반화하여, 동일한 어원 기반 명명 규칙을 쓰는 인접 도메인에
재사용 가능한 형태로 확장한다.

### 확장 대상 도메인 (우선순위 순)
1. **의약품 성분명(INN/USAN)** — 국제일반명(International Nonproprietary
   Names) 데이터셋 확보 후 커버리지 분석.
2. **화장품 성분표(INCI)** — 식약처 화장품 성분사전 또는 INCI 데이터베이스
   기반.
3. **농약/살충제 성분명** — 국립농업과학원 농약정보시스템 데이터 활용 가능성
   검토.

### 작업 범위
1. 기존 KOSHA-Braille 리포지토리(경로는 실제 위치로 알려줄 것) 구조 파악 —
   어원 사전(lexicon), 변환 규칙 엔진, 검증 스크립트 위치 확인.
2. 어원 분해 규칙 엔진을 도메인 독립적으로 리팩터링 — "라틴/그리스 어원 →
   형태소 분해 → 점자 매핑" 코어 로직과 "도메인별 사전/예외 규칙"을 분리.
3. 의약품 INN 데이터셋(WHO INN 리스트 등 공개 데이터 조사)을 입력으로 커버리지
   테스트 — 기존 어근 사전으로 몇 %가 커버되는지, 커버 안 되는 어근은 무엇인지
   리포트.
4. 결과를 CSV/JSON으로 정리해서 "도메인별 어근 커버리지 비교표" 산출.
5. 이 결과를 바탕으로 후속 브리프 리포트 초안(방법론 섹션 정도)을 마크다운으로
   작성.

### 산출물
- `docs/track-a-coverage-report.md` — 도메인별 어근 커버리지 분석 결과
- `data/inn_braille_mapping.csv` (또는 확보 가능한 도메인 우선)
- 리팩터링된 코어 엔진 코드 (기존 코드베이스 내)
- `docs/track-a-followup-methods-draft.md` — 후속 논문 방법론 섹션 초안

## 트랙 B — 화장품: 비조준(non-aim) 스캔 + AI 성분 요약 프로토타입

### 배경
물리적 점자는 화장품 같은 소형 포장에는 공간 제약으로 구조적 확장이 어렵다.
일반 QR코드는 시각장애인이 초점을 맞추기 어려워 실사용이 어렵고, NaviLens 같은
비조준(각도·거리 관대) 스캔 기술이 이미 식품 포장에 상용화된 사례가 있다
(영국 켈로그 코코팝스 시범 도입). 이 트랙은 그 구조를 화장품 성분 정보에
적용하는 프로토타입이다.

### 작업 범위
1. NaviLens API/SDK 또는 유사 오픈소스 대안(예: 대형 마커 기반 인식) 조사 —
   상용 API 라이선스 조건, 비용, 오픈소스 대체재 존재 여부 확인.
2. 화장품 성분표(INCI) 텍스트를 입력받아 AI(LLM)로 요약하는 파이프라인 설계:
   - 성분 목록 → 알레르겐/주의 성분 하이라이트
   - 라틴어원 성분명을 일반인이 이해하기 쉬운 설명으로 변환 (트랙 A의 어원
     분해 엔진 재사용)
   - 요약 결과를 TTS로 읽어줄 수 있는 텍스트 포맷으로 출력
3. 마커(비조준 스캔 코드)와 성분 요약 파이프라인을 연결하는 프로토타입 —
   실제 상용 API 없이도, 정적 마커 ID → 사전 등록된 성분표 매핑 정도의 목업
   수준으로 시작 가능.

### 하지 말아야 할 것
- 성분의 실제 피부 반응/독성학적 해석(안전성 판단)은 스코프 밖 — 이 트랙은
  "정보 접근성 인프라"만 다루고, 해석은 명시적으로 범위 밖으로 규정한다.

### 산출물
- `docs/track-b-navilens-feasibility.md` — 기술 조사 결과
- 성분 요약 파이프라인 프로토타입 코드
- `docs/track-b-followup-methods-draft.md`

## 트랙 C — 수어 지문자(fingerspelling) 인식 프로토타입

### 배경
화학물질명처럼 등록된 수어 어휘가 없는 전문용어는 한국수어에서 지문자로
표현되는 경우가 많다. 예전에 연속 수어 동작 인식(motion recognition)을
시도했으나 아마추어 수준에서 정확도를 못 냈던 경험이 있다. 이번에는 스코프를
좁혀서:
- 연속 문장 인식이 아니라 **단일 정적 손모양(지문자) 인식**으로 한정
- 원시 영상 픽셀 분류가 아니라 **MediaPipe Holistic으로 keypoint를 먼저
  추출**한 뒤, keypoint 시퀀스를 분류하는 훨씬 쉬운 문제로 변환

### 작업 범위
1. MediaPipe Holistic(Google, 사전학습·무료·실시간) 설치 및 손 keypoint 추출
   파이프라인 구축.
2. 한국수어 지문자(자음/모음) 데이터셋 조사 — 공개 데이터셋이 있는지 확인
   (없다면 소규모 자체 수집 방안도 같이 검토).
3. keypoint 기반 분류기(간단한 classifier 또는 학습 없이 DTW 거리 비교) 구현
   — 실시간 추론까지는 아니어도, 정지 이미지/짧은 클립 단위 분류로 시작.
4. 평가 시 person-independent split(같은 사람 손으로만 학습·테스트하지 않기)을
   반드시 적용 — 이게 빠지면 정확도가 실제보다 부풀려짐.
5. 정밀도/재현율/혼동행렬 등 표준 평가지표로 리포트 작성.

### 명시적 한계 (문서화만, 지금 풀지 않음)
- 조명, 손 각도, 피부톤, 손 크기 편차에 대한 강건성은 프로토타입 단계에서는
  다루지 않고 `docs/track-c-limitations.md`에 한계로 명시.
- 연속 수어 문장 인식으로의 확장은 이 트랙의 범위 밖.

### 산출물
- `docs/track-c-fingerspelling-eval.md` — 평가 방법론 및 결과
- 프로토타입 코드 (MediaPipe 파이프라인 + 분류기)
- `docs/track-c-limitations.md`

## 공통 원칙

### 전문가 개입은 전부 옵션(Optional)
트랙 A(점역사/화학 자문), B(피부과·화장품 전문가), C(수어 언어학자/CV 전문가)
모두 실제로 사람에게 검증을 의뢰할지는 별도 결정 사항이며, 이 프롬프트의
작업에는 포함하지 않는다. 다만 완전히 배제된 것은 아니므로, 각 트랙 산출물에
"전문가 검증 후보 항목" 섹션을 남겨서 나중에 의뢰서 작성 시 바로 쓸 수 있게
한다. 의뢰서 작성 시에는:
- 검증 대상을 최종 결과물 전체가 아니라 어근/규칙/keypoint 클래스 등 최소
  단위로 좁혀서 명시
- 검증 범위 밖 항목을 명시적으로 기재 (전수검사가 아님을 스코프에 못 박기)
- 비용/일정 관련 의사결정은 이 단계에서 하지 않는다

### 저널 제출은 이 단계에서 하지 않는다
세 트랙 모두 파이프라인/프로토타입 구축과 커버리지·평가 분석까지만 진행한다.
