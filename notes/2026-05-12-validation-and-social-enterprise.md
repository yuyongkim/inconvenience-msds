## Q2. 점역사 검수 / 점자 학습 / "잘못된 점자"의 의미

### 검수 워크플로우 — 샘플 감수가 표준

49K 전체 재점역이 아니라 체계적 오류 검출 목적:

```
[1단계] 샘플 추출 (랜덤 100~300 + 고위험 50~100, GHS H300대/발암성/폭발성)
[2단계] 점역사 감수 (오류율: cells per 1000)
[3단계] 인코더 규칙 패치 (pipeline/ko_braille.py) + 전체 49K 재export (3분)
[4단계] 재감수 (회귀 검증, 소규모)
```

**비용 감각**: 점역사 시급 3~5만원, 100개 chemicals (30~50쪽 분량) 감수 →
50~150만원선. 사회적 기업/공익 협업 명목 시 무상~할인 가능. 한국시각장애인연합회
점자정보화팀이 첫 컨택 포인트.

**본인이 점자 배워야 하나**: 읽기 fluency는 불필요. 2017 한국 점자 규정 PDF
(문체부 고시) 통독 1~2주는 필수 — 점역사가 "규정 X조 위반" 지적할 때 디버깅 가능
해야 함. 이미 pipeline/ko_braille.py 구현하면서 절반은 알고 있을 것.

### "잘못된 점자"가 의미를 바꾸는 사례

MSDS는 일반 문학 점자와 달리 안전 직결:

| 오류 유형 | 결과 |
|----------|------|
| 수표(⠼) 누락 | "1%"가 "ㄱ%"처럼 읽힘 → 농도 정보 소실 |
| 받침 오인 (ㄴ↔ㄹ) | "흡입" → "흡일" / "삼킴" → "삼김" |
| 부정문 점자 누락 | "삼키지 마시오" → "삼키시오" (정반대) |
| 약자 오용 | "벤젠" ↔ "벤진" (다른 물질, 다른 LD50) |
| 띄어쓰기 오류 | "물 100ml" → "물100ml" 단위 인식 실패 |
| GHS 그림문자 변환 오류 | 폭발성 → 인화성 카테고리 혼동 |
| 대문자 표시(⠠) 누락 | "CO"(일산화탄소) ↔ "Co"(코발트) |

마지막 행이 특히 위험 — 일산화탄소 응급처치(맑은 공기로 이동)와 코발트
응급처치(피부 세척)는 완전 다름. 점자 한 셀이 사람을 죽일 수 있음.

이게 "infrastructure-grade" 프레이밍이 수사가 아닌 이유 — 점자블록 한 칸 어긋남과
같은 구조의 리스크.

### 예비 사회적 기업 구조

```
[1] 예비 사회적 기업 (광역지자체 지정, 2~3년)
    ├─ 신청처: 시·도청 (서울이면 서울시 사회적경제과)
    ├─ 자격: 사회적 목적 + 수익 활동 + 거버넌스
    ├─ 혜택: 인건비 일부 지원 (참여인력 월 ~200만원선), 사업개발비
    └─ 심사: 사업계획서 + 면접

[2] 사회적 기업 (고용노동부 인증, 영구)
    ├─ 보통 예비 → 인증 코스
    ├─ 혜택: 법인세 감면, 우선구매 (조달청 등록 시 공공기관 의무 구매)
    └─ 더 까다로움: 매출, 사회적 목적 재투자 비율 등 검증
```

**KOSHA-Braille 적합 유형**:
- 사회서비스 제공형 (장애인 정보 접근권)
- 일자리 제공형 (시각장애 IT 인력 채용) — 가산점

**준비물**: 법인 설립, 사업계획서 (3년 재무), 레퍼런스/파일럿, 사회적 영향 지표

## Q3. 점자가 1:1 매핑인가, 수화처럼 별개 언어인가?

### 결론: 점자는 "다른 언어"가 아니라 "다른 표기 체계"

| | 점자 (Braille) | 수화 (Sign Language) |
|---|---|---|
| 본질 | 표기법 (script) | 언어 (language) |
| 한국 버전 | 한국어 점자 | 한국수어(KSL) |
| 한국어와의 관계 | 같은 언어, 다른 표기 | 완전 별개 언어 |
| 문법 | 한국어 문법 그대로 | KSL 고유 문법 |
| 변환 작업 | 점역 (transcription) | 번역 (translation) |
| 자동화 난이도 | 규칙 기반으로 가능 | 매우 어려움 |

비유:
- 점자 ≈ 한글을 로마자로 표기 / 모스 부호 — 같은 말, 다른 기호
- 수화 ≈ 한국어 → 일본어 번역 — 다른 말, 의미 매칭

점자가 수화 같은 별개 언어였다면 49K chemicals 3분 변환은 불가능. 가능했다는
사실이 점자가 표기 체계임을 증명.

### 1:1은 아니고 1:N + 규칙 기반

**1. 자모 분해 (음절 → 1~3셀 가변)**
- "가" = ⠫ (1셀)
- "강" = ⠫⠶ (2셀)
- "꽃" = ⠠⠅⠽⠞ (4셀)

**2. 약자 (contractions)**
- "것" → ⠸⠎ (3셀 → 2셀로 약자화)

**3. Indicator (지시 부호) — 같은 셀이 문맥에 따라 다른 의미**
- ⠼ 다음의 ⠁ = 숫자 "1"
- 일반 위치의 ⠁ = 자음 "ㄱ"
- ⠠ 다음의 a = 대문자 A
- ⠴ 다음의 a = 로마자 "a"

**4. 띄어쓰기 규칙이 한글 맞춤법과 다른 경우 있음**

### 점역사의 역할

- 기계 변환 = 자모/약자 매핑 규칙 적용
- 점역사 검수 = 문맥/가독성/규정 충돌 판단

예: "벤젠 1%" — 수표 위치, 단위 띄어쓰기, 화학식 표기. 규칙 3개 충돌 시 우선순위 판단.

### 프로젝트 관점

- **가능한 이유**: 점자가 표기 체계라서 자동화 가능. 수화 자동 통역은 학계 R&D 단계.
- **조심할 부분**: 규칙 시스템이라 규정 개정/예외 케이스마다 룰 수정 필요.
  영어 G2처럼 contraction 많은 시스템은 더 어려움 (73.2%).
- 한국어 점자 규정은 2017 이후 큰 개정 없어서 안정적.

## Q4. 영어 점자 / 자동화 / 책 출판과의 연계

### 영어 점자도 같은 원리 — 다만 더 복잡함

UEB (Unified English Braille):
- **Grade 1 (uncontracted)**: 거의 1:1, 알파벳 + indicator
- **Grade 2 (contracted)**: 약자/축약 ~180개, 단어 단위 압축

예시 G2 contractions:
```
"the"      → ⠮      (3자 → 1셀)
"and"      → ⠯      (3자 → 1셀)
"with"     → ⠾      (4자 → 1셀)
"mother"   → ⠍⠻    (6자 → 2셀)
"knowledge"→ ⠅      (9자 → 1셀)
```

영어 G2는 거의 "코드"에 가까움 — 같은 셀 ⠯이 단독 시 "and"이지만 다른 단어에
끼면 안 됨. 본 프로젝트 G2 decode 73.2%에서 막힌 이유.

| | 한국 점자 | 영어 UEB |
|---|---|---|
| 약자 개수 | ~50개 | ~180개 |
| 위치/문맥 의존성 | 중간 | 매우 높음 |
| 분야별 변종 | 적음 | 많음 (음악/수학 별도) |
| 본 프로젝트 정확도 | KR 직접 점역 1.000 | G2 decode 0.732 |

영어권 확장은 liblouis 같은 오픈소스 점역기가 이미 있어서, 본 프로젝트 가치는
**한국어 + 도메인 특화(화학/안전)**에 집중하는 게 합리적.

### "수요 있건 없건 자동으로 되는 거 아닌가?" — **이게 비즈니스 모델의 정중앙**

#### 현재 한국 점자 출판의 시장 실패

```
연간 한국 신간 도서: ~6만 종
연간 점자판 제작: ~1,000 종 이하 (2% 미만)

원인:
- 점역사 책 1권당 수십~수백 시간 작업
- 출판사 비용 회수 불가 (시각장애 독자 시장 작음)
- "수요가 적어서 안 만듦" → "안 만드니까 독자도 못 늘어남" 자기충족 예언
```

#### 본 프로젝트가 깨는 가정

- 전통: **수요 → 점역 결정 → 점역사 투입 → 1권 산출**
- 자동화: **공급 자동화 → 전수 변환 → 수요는 사후 발견**

MSDS 49K를 3분에 변환한 게 증명한 것 — **marginal cost ≈ 0**.

#### 일반화

```
[디지털 텍스트 코퍼스]  ─자동 점역→  [점자판 코퍼스]
   ├─ MSDS 49K          (완료)
   ├─ KISCHEM 7,189     (완료)
   ├─ FDA drug labels   (완료)
   ├─ 식품 알레르겐 19  (완료)
   ├─ 법령/판례         (확장 가능)
   ├─ 공문서/안내문     (확장 가능)
   ├─ 학술 논문         (확장 가능)
   └─ 일반 도서 EPUB    (확장 가능)
```

#### 사회적 기업 수익 모델 — 수요 측이 아닌 공급 측 의무 기반

| 수익 채널 | 근거 법령/제도 | 타깃 |
|----------|--------------|------|
| B2G 공공기관 점자 자료 구축 | 장차법 21조 (정보 접근 의무) | 정부/지자체/공기관 |
| 조달청 우선구매 | 사회적 기업 우선구매제도 | 모든 공공기관 |
| B2B 출판사 EPUB→점자 변환 | 출판법 / 도서관법 | 출판사 |
| B2B 제약/화학 라벨 점자 | 의약품 안전사용 의무 | 제약사/화학기업 |
| B2G 도서관 점자 디지털 라이브러리 | 국립장애인도서관 사업 | 도서관계 |

핵심: 수익이 **법적/제도적 의무**에서 나옴. 점자블록 깔고 돈 받는 게 통행량
수요 때문이 아니라 법령 때문인 것과 같음.

#### 진짜 IP는 어디 있는가

자동화 자체는 복제 가능. 본 프로젝트의 진입 장벽:

1. 도메인별 어휘 사전 — 화학물질 13K, 의약품, 법령 용어 등
2. 검수 워크플로우 — 안전 직결 분야의 회귀 검증 시스템
3. 협업 기관 네트워크 — 점역사/시각장애 단체와의 신뢰
4. 규모 입증 (track record) — "49K 무사고 변환" 같은 숫자
5. 분야별 특수 케이스 핸들링 — GHS 그림문자→텍스트, 화학식 indicator 처리
