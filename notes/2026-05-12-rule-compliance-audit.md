## 1. 양호 영역 (변경 불필요)

### 1.1. 자모 매핑

`pipeline/ko_braille.py` L67-145의 `_CHO_DOTS`, `_JUNG_DOTS`, `_JONG_DOTS`
딕셔너리는 다음 기준으로 검증됨:

- liblouis ko-g1 점자 테이블 (오픈소스 표준)
- 참조 구현 `hangul-braille-converter` (hyonzin) — 442/442 일치
- 한국 점자 규정 별표 1~3과 직접 매핑 확인

세부 사항:
- 된소리는 6점(⠠) prefix + 기본 초성 (예: ㄲ = ⠠ + ㄱ)
- 겹받침은 각 자음의 종성 패턴을 2셀로 분리 (예: ㄳ = ㄱ종성 + ㅅ종성)
- 복합모음 ㅒ/ㅙ/ㅞ/ㅟ는 2셀, ㅚ는 1셀로 규정 일치

### 1.2. 지시 부호 모드 전환

`encode_korean_braille()` L205-291:
- 수표(⠼): 숫자 모드 진입, 다른 문자 만나면 해제 — 정상
- 로마자표(⠴): 영문 모드 진입, 한글/숫자 만나면 해제 — 정상
- 대문자표(⠠): 영문 모드 내 대문자 처리 — 정상

## 2. 갭 영역 (점역사 감수 시 우선 확인)

### 2.1. ❌ 괄호/따옴표 짝 구분 — **명확한 규정 위반**

**현재 코드** (L186-198):
```python
KO_PUNCT_BRAILLE = {
    '-': dots_to_braille('3-6'),    # ⠤
    '(': dots_to_braille('3-6'),    # ⠤ — 하이픈과 동일!
    ')': dots_to_braille('3-6'),    # ⠤ — 하이픈/여는괄호와 동일!
    '"': dots_to_braille('2-3-6'),  # ⠶ — 물음표와 동일!
}
```

**한국 점자 규정 (별표 5)**:
- 여는 소괄호 `(` → ⠦ (2-3-6) + ⠄ 등 구분 부호
- 닫는 소괄호 `)` → ⠠ + ⠴ (3-5-6) 등 구분 부호
- 큰따옴표 여는 `"` → ⠦ (특정 패턴)
- 큰따옴표 닫는 `"` → ⠴ (특정 패턴)

(정확한 셀 패턴은 규정 별표 직접 참조 필요 — 위는 대략)

**영향**: 화학식 표기에서 치명적. 예:
- `"벤젠 (C₆H₆)"` → 점자에서 괄호 구분 불가능 → 화학식 경계 모호화
- 본 프로젝트 MSDS는 괄호 사용 매우 빈번 (CAS 번호, 화학식, 약자 등)

**우선순위**: HIGH. 점역사 감수 전이라도 규정 별표 확인 후 수정 권장.

### 2.2. ❌ 약자 (contractions) 미구현

한국 점자 규정 별표 6~8에서 정의하는 약자:
- 음절 약자: 것, 까, 나, 다 등 ~20개
- 단어 약자: 그래서, 그러나, 그리고, 그러면, 그러므로, 그러니까 등 ~20개
- 약어 표기: 사람 이름, 지명 등

**현재 상태**: 완전히 미구현 (모든 음절을 자모 분해로 처리)

**판단**: 의도적 미구현일 가능성 — 안전 직결 도메인(MSDS)에서는 약자 사용을
지양하고 풀어쓰기를 선호하는 점역 관행 존재. 일반 도서 점역과 다른 영역.

**점역사 확인 필요**: 본 도메인에서 약자 사용 권장 여부. 후속 도메인(법령,
일반 도서) 확장 시에는 반드시 구현 필요.

### 2.3. ❌ 줄임표 (...) 미구현

현재 `.` 단일 문자만 처리 (2-5-6). 연속 `...`는 점이 3번 반복되는 형태로
출력되는데, 한국 점자 규정에서 줄임표는 별도 부호 (보통 ⠐⠐⠐ 또는 특정
패턴).

**영향**: MSDS 텍스트에서 줄임표 빈도는 낮으나, "..." 또는 "····" 형태로
나타날 경우 잘못 인코딩됨.

**우선순위**: LOW.

### 2.4. △ 외국어 표시 — 영어 외 미지원

`encode_korean_braille()` L256-279: ASCII 알파벳만 영어 점자로 처리.
일본어 가나, 중국어 한자는 `result.append(ch)`로 원문 그대로 통과.

**한국 점자 규정**: 외국어 표시는 언어별 indicator가 다름. 영어는 ⠴, 일본어는
별도 지시 부호.

**영향**: MSDS 데이터에서 일본어/중국어 출현 빈도는 낮으나 (CAS 외국 문헌
인용 시), 데이터셋에 포함된 경우 처리 누락.

**우선순위**: LOW. 도메인 확장 시 검토.

### 2.5. ❌ 화학식 특수 처리

화학식 표기:
- 아래첨자: H₂O의 ₂, CO₂의 ₂
- 위첨자: 동위원소 ¹⁴C, 이온 Cu²⁺
- 결합 표시: -, =, ≡

**현재 상태**: 모두 미구현. ₂는 Unicode 그대로 출력되어 점자로 인식 불가.

**한국 점자 규정 + 수학점자/과학점자 규정**: 아래첨자/위첨자는 별도 indicator
존재 (한국 점자 규정 별도 부속서 또는 수학점자 규정 참조).

**영향**: MSDS는 화학식이 곳곳에 등장 → 직접적 영향. 예:
- `H2SO4` (ASCII 표기): 정상 처리 (숫자로 인식)
- `H₂SO₄` (Unicode 첨자): 깨짐

**확인 필요**: 본 프로젝트 데이터 원본에서 화학식이 어떤 표기로 들어오는지
검증. 만약 모두 ASCII (H2SO4)라면 우선순위 낮음, Unicode 첨자가 섞여 있으면
HIGH.

**우선순위**: 데이터 확인 후 결정.

### 2.6. ❌ 단위 점자

m, kg, ml, mg/L, ppm, mmHg, °C 등 단위는 현재 영문 indicator + 각 알파벳을
풀어 점역. 그러나 한국 점자 규정에는 단위에 대한 별도 약자/관행 존재
(공학 점자 영역).

**판단**: MSDS 도메인에서는 단위가 매우 빈번하므로, 점역사 감수 시
"단위 표기를 약자로 할지 풀어쓰기로 할지" 정책 결정 필요.

### 2.7. ❌ 수학 기호

°C, %, ×, ÷, ±, ≤, ≥, → 등.

- `%` — 한국 점자 규정에 매핑 존재 (⠩ 등)
- `°` (도) — 규정 매핑 존재
- 나머지는 수학점자 규정 영역

**현재 상태**: `%`는 통과 (변환 안 됨), `°`도 통과. MSDS에 빈번한 "25°C",
"100%" 등이 부분적으로만 처리됨.

**우선순위**: MEDIUM. % / ° 정도는 추가 권장.

### 2.8. △ 띄어쓰기 규칙

한글 맞춤법 띄어쓰기 ≠ 한국 점자 띄어쓰기. 예:
- "할 수 있다" — 한글: 띄움 / 점자: 일부 약자 사용 시 붙임
- 조사 + 의존명사 — 점자에서 띄어쓰기 규정 별도

**현재 코드**: 입력 텍스트의 띄어쓰기를 그대로 유지 (공백 → ⠀). 점자 규정에
맞는 띄어쓰기 재처리 없음.

**판단**: 본격적 띄어쓰기 재처리는 NLP 영역. 점역사 감수에서 "점자 띄어쓰기
규정 위반" 사례 수집 후 룰 기반 패치가 현실적.

**우선순위**: 점역사 감수 후 결정.

## 4. 점역사 감수 의뢰 시 우선 검토 요청 항목

본 자가 점검의 한계는 "규정 문헌 vs 코드"만 비교했다는 점입니다. 점역사가
실제 변환 결과를 손가락으로 읽었을 때만 드러나는 이슈가 별도로 존재합니다.
감수 요청 시 다음 항목을 우선 검토 요청:

1. **자모 패턴의 의미 명확성** — 자모 매핑은 일치하지만, 실제 단어 단위로
   읽었을 때 모호함이 발생하는지
2. **화학물질명의 가독성** — "벤조[a]피렌", "1,2-디클로로에탄" 등 복합
   명명법 처리
3. **GHS H/P statement의 점자 표현** — "삼키지 마시오" 같은 안전 문구의
   부정문 처리 명확성
4. **CAS 번호 표기** — "71-43-2" 같은 하이픈 포함 숫자열의 점자 표현
5. **농도/온도 표기** — "0.5 mg/L", "25°C" 등의 단위 결합 표기
6. **단락/줄바꿈** — 점자 페이지 레이아웃 관행 (현재 코드는 단순 `\n` 보존)
7. **약자 사용 권장 여부** — 현재 약자 미구현, 적용 권장도 판단

## 5. 결론

자모 단위 점역은 견고하고, 라이브러리 검증 + 독립 구현 일치도 100%로
**기초적 점역 정확성은 확보된 상태**.

다만 **MSDS 도메인 특수 요소**(화학식 첨자, 괄호 구분, 단위 표기)에서
명확한 갭이 있고, 일부는 **규정 위반** 수준 (괄호/따옴표 짝 미구분).

점역사 감수 의뢰 전:
- (a) 괄호/따옴표 짝 수정 (HIGH 1번)
- (b) 데이터 원본 첨자 표기 조사 (HIGH 2번)

이 두 가지를 먼저 처리한 후, 깨끗한 샘플로 점역사 감수 의뢰가 효율적임.

후속 도메인(의약품/법령) 확장 시에는 약자 구현이 필수.
